# 영상 담기

사용자의 말과 링크를 **공연 하나당 요청 JSON 하나**로 바꾸고 `node scripts/archive.mjs add`로 담아요. JSON 파일을 직접 고치지 않아요.

## 1. 지금 상태 보기

```bash
node scripts/archive.mjs status            # 그룹·멤버(별칭)·곡(별칭)·최근 공연
node scripts/archive.mjs events 르니에      # 그 그룹 공연 목록 (같은 공연이 이미 있는지)
```

- 그룹이 없으면 → 사용자에게 확인한 뒤 `edit-archive` 스킬의 그룹·멤버·곡 추가부터 해요.
- 행사명은 기존 표기를 따라요(`events` 출력). 자주 쓰는 표기: `뮤직뱅크`, `인기가요`, `쇼! 음악중심`, `엠카운트다운`, `더 쇼`, `쇼챔피언`. 축제·콘서트는 행사 이름 그대로.
- 같은 그룹·같은 날짜에 행사가 둘이면 `label`로 나눠요(`사전녹화`, `2부`, `리허설`). 본방은 label 없이.

## 2. 요청 JSON 만들기

링크를 **날짜·행사(공연)별로 묶어서** 공연마다 하나씩 만들어요. 링크 하나에 날짜가 다르면 공연도 다른 거예요.

```json
{
  "group": "르니에",
  "date": "2026-10-23",
  "show": "뮤직뱅크",
  "label": "",
  "note": "레드 투피스",
  "setlist": ["Paper Moon", "Static"],
  "videos": [
    { "url": "https://youtu.be/AAAAAAAAAAA" },
    { "url": "https://youtu.be/BBBBBBBBBBB?t=31", "members": ["유나"], "song": "Paper Moon" },
    { "url": "https://www.youtube.com/shorts/CCCCCCCCCCC", "members": ["단체"], "song": "Static", "tags": ["세로"] },
    { "url": "https://youtu.be/DDDDDDDDDDD", "type": "full", "songs": [{ "song": "Paper Moon", "t": 0 }, { "song": "Static", "t": "3:34" }] }
  ]
}
```

필드 규칙 (전체 형식: `node scripts/archive.mjs add --help`):

| 필드 | 언제 넣나 |
|---|---|
| `members` | 사용자가 멤버를 말했거나 제목에 없을 때. 단체 직캠은 `["단체"]`, 유닛·페어는 `["도희","세린"]`. 이름·영문 별칭·id 모두 돼요 |
| `song` | 그날 곡이 둘 이상이고 제목에 곡이 없을 때. 곡 구분 없는 축제·콘서트 전체 영상은 `"전체 공연"` |
| `songs` | 영상 하나에 두 곡 이상(송출본 등). 곡마다 시작 시각 |
| `type` | 제목에 직캠/풀캠 단서가 없고 멤버도 없을 때 (`full` 또는 `fancam`) |
| `t` | 곡 시작 초. URL에 `t=`가 있으면 자동 |
| `source` | 사용자가 공식/팬이라고 말했을 때만. 방송사 채널(KBS Kpop, MBCkpop 등)은 자동으로 `official` |
| `tags` | 사용자가 말한 것(리허설, 사전녹화, 얼빡, 세로, 4K, 엔딩). 제목에서 읽히는 것은 자동 |
| `setlist` | 사용자가 그날 무대 순서를 말했을 때. 없으면 영상의 곡 순서로 만들어져요 |
| `note` | 의상 메모 등 사용자가 말했을 때 |
| `pin`, `thumbPos` | 사용자가 "이걸 대표로", "위쪽이 보이게" 같이 말했을 때 |

새 곡이면 사용자가 곡명을 말한 경우에 한해 `--create-songs`를 붙여요(그룹 곡 목록에 추가돼요).

요청 파일은 저장소 밖(예: 스크래치 폴더)에 두거나 `-`로 표준 입력에 넘겨요. 저장소에 커밋하지 않아요.

## 3. dry-run → 확인 → 실행

```bash
node scripts/archive.mjs add /path/req.json --dry-run
```

- `+` 줄: 담길 영상. `자동:` 은 제목에서 읽은 값이에요. 제목이 사용자 말과 어긋나면(다른 멤버 등) 요청에 값을 명시해요.
- `!` 경고: 이미 담은 영상(건너뜀), 제목 날짜가 공연 날짜와 다름, setlist에 없는 곡, 같은 날 다른 공연 등. 날짜가 다르면 사용자에게 확인해요.
- `✗ 정할 수 없는 영상`(종료 코드 2): 아무것도 쓰지 않았어요. 사용자에게 그 링크의 멤버·곡·종류를 물어 요청을 고쳐요. 일부만 먼저 담아 달라고 하면 `--skip-invalid`.
- 제목을 못 불러왔다는 경고가 나오면(네트워크 차단) 사용자에게 그 사실을 알리고, 멤버·곡·종류를 직접 넣거나 물어요. 제목·채널을 지어내지 않아요(빈 채로 둬도 검증은 통과해요).

문제가 없으면 `--dry-run` 없이 실행하고, 끝에 `node scripts/archive.mjs validate`.

## 4. 커밋·PR·merge

`CLAUDE.md`의 Git 흐름대로. 커밋 메시지: `담기: <그룹> <날짜> <행사>[ <label>] 영상 N개`.

## 5. 사용자에게 보고

- 공연별: 새로 만든 공연인지 기존 공연에 더했는지, 담은 영상 수, 멤버·곡 요약, 자동으로 정한 값.
- 건너뛴 링크와 이유(이미 담음 → 어느 공연에 있는지).
- 볼 주소: 도구 출력의 `보기: index.html#g=..&e=..`를 Pages 주소 뒤에 붙여서.

## 예: 사용자 말 → 요청

> “르니에 10월 30일 엠카 직캠들이야. 유나, 도희 거고 마지막은 단체. 곡은 전부 Paper Moon” + 링크 3개

```json
{ "group": "르니에", "date": "2026-10-30", "show": "엠카운트다운", "setlist": ["Paper Moon"],
  "videos": [
    { "url": "<1>", "members": ["유나"] },
    { "url": "<2>", "members": ["도희"] },
    { "url": "<3>", "members": ["단체"] } ] }
```

> “하이디어 사녹이랑 본방 둘 다” → 같은 날짜로 요청 두 개: 하나는 `"label": "사전녹화"`, 하나는 label 없이.
