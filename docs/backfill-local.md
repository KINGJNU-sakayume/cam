## 이어서 하기

```bash
git fetch && git checkout data/2026-11-17-bf2-g7 && git merge --ff-only origin/main   # 시작 전에 다른 세션의 새 data/* 브랜치가 있는지 먼저 확인
bash scripts/backfill/chain.sh g7 "2024-07-01 2024-09-30 2024q3" "2024-10-01 2024-12-31 2024q4" "2025-01-01 2025-03-31 2025q1" "2025-04-01 2025-06-30 2025q2" "2025-07-01 2025-09-30 2025q3" "2025-10-01 2025-12-31 2025q4"
```

- 기본 속도: 동시 3개(`JOBS`), 요청 간격 0.4초(`HARVEST_GAP_MS`). 분기 하나 약 45분. 429·빈 응답이 오면 `scripts/lib/yt.mjs`가 스스로 간격을 두 배로 늘리고, `scripts/harvest-slow.mjs`가 실패분만 쉬었다가 다시 돌려요. 더 천천히: `JOBS=1 HARVEST_GAP_MS=1000 bash scripts/backfill/chain.sh ...`
- 분기가 끝날 때마다(결과: `.cache/bf2/g7-<분기>/`):
  1. `bash scripts/backfill/prep.sh .cache/bf2/g7-<분기> .cache/work/g7-<분기>` — 분류(classify) → 기존 공연과 맞추기(match) → dry-run 두 번(finalize)
  2. `.cache/work/g7-<분기>/final-dry.txt`를 읽고 `manual.json`으로 고쳐요:
     - `tour`: `[{ "re": "BORN TO BE|WORLD TOUR", "not": "TUNNEL", "name": "ITZY 2ND WORLD TOUR BORN TO BE" }]` — 제목의 투어 이름+도시를 "<name> <도시>"로 통일
     - `drop`: 무대 아닌 영상(커버·예능·VCR·토크·수상)의 제목 조각이나 유튜브 ID
     - `set`: `{ "<유튜브ID>": { "date", "show", "song"/"songs", "members", "type" } }`
     - 고친 뒤 `node scripts/backfill/finalize.mjs .cache/work/g7-<분기>`
  3. `bash scripts/backfill/apply.sh .cache/work/g7-<분기> "담기: 있지 <분기> 무대 영상 N개 (2차 수집)"` — 담기 + 썸네일 얼굴 위치 + validate + 커밋
  4. 새로 생긴 곡을 확인해요. 투어 이름·VCR처럼 곡이 아닌 이름이면 지우지 말고 `node scripts/archive.mjs set <곡id> kind=other`, 커버면 `kind=cover`. 영상을 지울 때는 사용자에게 먼저 물어요.
- 그룹이 끝나면 `main`이 브랜치의 조상인지 확인하고(fast-forward) `git push origin HEAD:main`.

## 판정에서 배운 것 (같은 실수 반복하지 않게)

- 방송 날짜가 아니라 **공연 날짜**로: 더 시즌즈(녹화일), 뮤직뱅크 글로벌 페스티벌(현지 공연일), 연말 결산 재방송은 담지 않음.
- 투어 이름이 곡으로 읽힘: CHOOM·Andless·PUREFLOW·TUNNEL VISION·Visionary Vision. 공연 setlist가 한 곡뿐이면 모르는 곡이 그 곡으로 들어가니 dry-run의 곡이 제목에 있는지 꼭 확인.
- 대학 이름이 있으면 같은 날 음악방송보다 축제 우선. "코리아"의 "리아", "Sullin"의 "린"처럼 멤버 이름이 다른 낱말에 섞여 읽힘.
- 다른 팀의 커버(댄스팀·오디션 프로그램), 리액션, 가수대기석·수상 소감, 브이로그, 위버스·인스타 라이브는 무대가 아님.
- 유튜브가 잠깐 막으면 "영상 정보 N개 실패"가 나오지만, 나중에 같은 명령을 다시 돌리면 대부분 받아짐.
